Autonomous Intelligent Patching

From zero-day to fully patched in minutes. Six AI agents discover vulnerabilities, predict risk, reason about history, execute phased rollouts, self-heal on failure, and learn from every outcome.

7AI Agents
6Stages
A2AMessage Bus
∞Feedback Loop
1DISCOVERVulnerability Agent

Queries Red Hat Insights for CVE details and identifies all affected systems.

Backend
INSIGHTS_MCP_ENDPOINT — MCP server for Insights API
Fallback
Demo hosts with pre-configured profiles when Insights is unavailable
2PREDICTRisk Agent

ML model calculates composite risk score per host. Classifies as ok (auto-patch) or review (needs approval).

Backend
RISK_URL — RHOAI model serving endpoint
Metrics
Failure probability, impact probability, risk classification
3REASONRisk + Automation Agents

RAG searches historical patch records. Produces a phased deployment strategy (Test → Canary → Production).

Backend
LLAMA_STACK_URL + VECTOR_DB_ID for RAG
Output
History analysis, host decisions, phased strategy
4EXECUTEAutomation + Diagnosis

Generates playbook via Lightspeed, publishes to GitHub, creates AAP workflow with approval gate. Phased execution with auto-failure detection, rollback, and AI-driven remediation.

Backend
AAP_BASE_URL + GITHUB_TOKEN
Phases
Test → Canary → Production
5LEARNLearning Agent

Records outcomes as training events. Updates RAG vector store. Feeds data pipeline for continuous model improvement.

Pipeline
Outcomes → Feature Store → OpenShift AI → Model Registry → KServe
Loop
Each patch cycle improves future risk predictions
$ROIROI Agent

Calculates financial value: engineering effort avoided, reduced exposure, automation reuse, faster recovery. References published industry benchmarks.

Quick Start
  1. Pick a CVE from the dashboard or enter one manually
  2. Click Patch — watch pipeline stages light up
  3. Monitor agent-to-agent messages in the sidebar
  4. Click any pipeline stage to jump to its detail card
  5. At the approval gate, click Approve to continue
  6. Watch phased execution, failure detection, AI remediation, and learning

Scene-by-scene guide for presenting AIP. Read the Say sections aloud; Watch for notes tell you what to point at.

Common Questions
What if backends aren't configured?
Every stage tries real APIs first and falls back to demo data.
Where does the LLM run?
Llama Stack on OpenShift, using locally-hosted Llama model. No data leaves your infrastructure.
Is the human always in the loop?
Yes, at the approval gate before execution. Post-approval, rollback and remediation are automatic.
What Red Hat products are involved?
Insights, Ansible Automation Platform, Ansible Lightspeed, OpenShift AI, and Llama Stack.
