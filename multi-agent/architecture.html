Why the Supervisor owns the loop. The cycle spans three agents — Patching reports the failure, Info diagnoses it, Patching retries. Only the Supervisor sees all of it, so the counters and the stop decision live there. Agents stay stateless and single-purpose.
Rollback failure is EXIT C immediately. A half-patched host is the worst possible state — stop the phase and page a human rather than attempting a fix on top.
LLM down during diagnose? Fall back to a rule table of known failure signatures (drain timeout, disk full, lock held, service restart). No match → EXIT B. Never guess.

Exit paths — decided by the Supervisor

EXIT A  healedRetry passes the health check. Host patched, rollout resumes, outcome written to training data.
EXIT B  abandonedAttempts exhausted, repeat fix, or approval denied. Host left rolled back, healthy, unpatched. SNOW ticket raised — rollout continues with other hosts.
EXIT C  abortedToo many hosts failed, project unsynced, or rollback failed. Remaining hosts untouched, operator escalation, nothing half-applied.

Fallback principles

1Labelled, never silent. Every degraded result carries source and degraded:true. A fallback that works but tells nobody is a bug.
2Degrade on reads, fail closed on writes. Missing history or a heuristic score — proceed. Approval, project sync and rollback — stop.
3Visible before approval. The patch plan must state which inputs were degraded before anyone approves; the Results agent records it for later correlation.
soft — degrade & continue hard — fail closed decision point Supervisor-owned
